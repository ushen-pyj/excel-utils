# Excel Utils · Windows 桌面表格工具

Excel Utils 是一个离线使用的 Windows x64 客户端。左侧 **主页** 显示最近工作簿，**打开** 用于浏览本地 XLSX，**工作区** 用于打开整个文件夹，**工具** 用于批量处理财务明细。打开工作簿后，可在同一窗口的工作簿标签里使用 ONLYOFFICE 原生表格界面。

## 安装与使用

运行 `dist/ExcelUtils-Setup-x64.exe` 安装，或直接运行完整发布目录中的 `dist/ExcelUtils/ExcelUtils.exe`。可移动分发时请复制整个 `ExcelUtils` 目录。安装包内置 Qt、CEF、表格编辑器及本地转换器。用户无需另装 ONLYOFFICE、Excel 或 Node.js。

1. 点 **打开**，首次使用时点 **打开文件**，已有最近文件夹时点 **浏览**，选一份本地 `.xlsx`。也可以从主页最近文件列表打开工作簿。
2. 编辑单元格，按回车提交输入。点编辑器的保存按钮或按 `Ctrl+S` 写回原文件。
3. 退出应用并重启，在 **主页** 点击刚才的文件。**打开** 页会显示该工作簿所在的文件夹。

最近记录和缓存存储在当前用户的应用数据目录，与官方桌面编辑器各自独立。进入 **工作区** 时会恢复上次的文件夹，左上角可切换最近 20 个工作区。单击左侧目录树中的文件或文件夹可高亮选中。双击 XLSX 会在右侧打开工作簿标签，双击文件夹会展开或折叠。从工作区退出后，直接启动应用会回到原工作区。标签保留原顺序，启动时只加载上次选中的工作簿，其余工作簿在首次切换到对应标签时加载。文件已移走时会跳过该文件，原先选中的文件不可用时会显示第一个可用标签。点击右上角的工具图标可查看全部工具。选中的工具会在当前工作区的对话框中打开。关闭有修改的工作簿时会询问是否保存。

### 工作区搜索

知道文件名时，点工作区顶部的 **快速打开**，或按 `Ctrl+Shift+O`。输入文件名或相对路径，可用空格组合目录和文件名片段，例如 `华东 预算`。用上下键选择，回车打开，Esc 返回。已打开的文件会复用原标签。同一工作区内同时打开同名文件时，标签会显示相对路径，方便区分。也可以在启动时直接传入文件夹路径，例如 `ExcelUtils.exe "D:\报表\月结"`。

工作区左侧有两个独立入口。在 **文件**（`Ctrl+Shift+E`）中，选中目录，点标题旁带加号的文件图标，输入名称并按回车，即可在该目录创建并打开一个空白 XLSX。选中文件时建在同级，未选择时建在工作区根目录。

在 **搜索**（`Ctrl+Shift+F`）中输入关键词，可查找当前文件夹及子目录内的 XLSX，包含隐藏工作表，支持中文、英文大小写不敏感的部分匹配、数值和公式。结果按工作簿分组，可展开或折叠，每项显示匹配片段、工作表名和单元格地址。单击结果或按回车可定位到可见工作表中的单元格。隐藏工作表会在结果中标明。选中结果后点击 **复制位置**，或在结果列表按 `Ctrl+C`，可复制工作簿路径和单元格地址。按 Esc 返回文件视图，再次切到搜索时保留查询和结果。工作区内可用 Ctrl+Tab 和 Ctrl+Shift+Tab 前后切换工作簿，目录树会跟随当前标签。

点击搜索框旁的 `.*` 可切换正则表达式搜索。输入 `^AB-\d{4}$` 可查找完整的编号，如 `AB-2026`。正则默认忽略大小写，可用 `(?-i:...)` 为指定部分启用大小写匹配。表达式无效或匹配超时时，搜索面板会显示提示。

进入工作区时，后台会为已保存的文件建立本机索引。再次查询时复用索引并检查增删改，编辑器保存后也会更新。点击「刷新」可完整重建当前工作区的索引。无法读取的项目会显示数量，悬停可查看原因。

### 财务工具

在 **工具** 里选择操作，添加一个或多个本地 `.xlsx`。每个来源独立设置工作表、表头行和明细起止行。表头和样例随范围更新。有列映射的工具可把设置存为本机模板，下次按列名套用。

本程序中已打开的工作簿可直接作为来源。工具在后台读取选入时的已保存快照，编辑器可继续使用。要把后续编辑用于分析，请先保存，再移除并重新添加该来源。输出需另存，当前正在编辑的工作簿和输入文件均受覆盖保护。

| 操作 | 配置和结果 |
| --- | --- |
| 合并明细 | 同名列自动对齐。在“设置输出列名”中，可把“成本中心”和“部门”命名为同一列，或留空跳过。若所选范围有数据的列缺少表头，来源卡会标出列号和样例，须填写输出名称或勾选跳过。结果附来源工作簿、工作表和行号。 |
| 分类汇总 | 每个来源分别选分组列与金额列，按组输出笔数、金额和总计。可用于单份费用表，也可一次统计多家部门的清单。 |
| 两表对账 | 选择双方的核对键和金额列，可交换左右表。点击核对状态可预览该状态的前 20 行，导出包含全部记录。双方有共同结算号时，可开启一对多、多对一核对，逐行列出候选组，供人工确认。 |
| 同表头合并 | 自动识别各表表头，按首表列序预览每个来源的明细。可调整识别结果、检查缺列或多列，再合并并另存为。写入期间可查看进度、行数或取消。 |
| 按列拆表 | 选部门、客户等分组列以及允许导出的字段，一组一个独立 XLSX。结果 ZIP 内附拆分清单，可按组核对笔数和金额。拆表及发票查重可逐来源设置是否跳过小计和合计行，默认跳过，结果显示跳过的行数。 |
| 发票查重 | 对比本期与历史台账。可指定发票代码及报销单号，区分同一报销单的多行费用，输出待复核的票号和来源行。 |
| 宽表转明细 | 选中要展开的列，生成原列名、值及源行号。空值跳过，零值保留，可选择沿用上一行的标识字段。 |
| 往来账龄 | 先选单据，再选逐笔核销明细。按截止日还原未结余额和逾期天数，按区间列出，单列未认领核销和贷方余额。 |
| 预算差异 | 先选预算，再选实际，可交换两表。差额按实际减预算计算，分别标明“无预算有发生”和“预算合计为零”。横排月份可先用宽表转明细转换。 |

同表头合并、按列拆表和发票查重在导出期间关闭主窗口时，可选择 **完成后退出**、**取消任务并退出** 或 **继续使用**。

同表头合并会去除列名两端空格，区分大小写，允许调换列序。列名重复、缺列、多列或有数据的列缺少表头时，会提示具体来源。空行跳过，公式取已保存的计算结果，金额、日期和带前导零的文本沿用原值。单张结果最多容纳 1,048,575 行明细和一行表头。可在“明细末行”中排除表尾合计。

**大表实测**　在 Windows x64、i7-12700KF 和本地磁盘上，使用 6 列模拟流水，列序及表头位置各不相同。每组运行三次，使用系统默认文件缓存。耗时取中位数，包含启动合并进程、读取输入和写完压缩 XLSX。样本生成、人工选文件和独立读回校验在计时区间之外。

| 工作负载 | 明细行数 | 耗时 | 合并进程峰值工作集 |
| --- | ---: | ---: | ---: |
| 10 万行 + 20 万行 | 300,000 | 3.01 秒 | 40.0 MiB |
| 10 万行 + 20 万行 + 20 万行 | 500,000 | 5.04 秒 | 40.1 MiB |
| 同一 50 万行数据，第三份改用共享字符串存储 20 万个不同流水号 | 500,000 | 4.67 秒 | 53.0 MiB |

上述峰值仅统计合并进程。列数、文本长度、来源文件中的不同共享字符串数量和磁盘速度都会影响实际结果。工具页完成后显示本次合并的行数和用时。

本次更新用东区、南区、西区三份样表复测，识别表头及读取每表三条样例耗时约 0.27 秒。单次合并 50 万行耗时 7.01 秒，峰值工作集 40.2 MiB。另用 50 万行、4 列的支出表测试拆分，计时含工作进程启动及 ZIP 写完。每种规模各运行一次，独立读回各组 XLSX 核对行数及金额。

| 输出组数 | 拆分耗时 | 工作进程峰值 |
| ---: | ---: | ---: |
| 10 | 7.70 秒 | 43.5 MiB |
| 100 | 8.56 秒 | 60.6 MiB |
| 500 | 14.15 秒 | 93.5 MiB |

金额运算按同一币种、元和分处理，支持负数和带千分位的文本金额。处理前检查明细范围，排除模板中的小计、合计和备注行。导出的明细保存公式上次计算的值。业务场景参考[微软追加查询](https://support.microsoft.com/zh-cn/excel/append-queries-power-query)、[数据透视表求和](https://support.microsoft.com/zh-cn/excel/sum-values-in-a-pivottable)及[财政部电子凭证会计数据标准应用指南](https://kjs.mof.gov.cn/zt/kuaijixinxihuajianshe/dzpzkjsjbzshsd/czznhjswd/202505/P020250519337890192554.pdf)。

## 架构与源码

| 部分 | 入口 | 责任 |
| --- | --- | --- |
| Qt 宿主 | `apps/desktop/main.cpp`、`workbook_window.cpp` | 初始化 CEF、配置本地路径和用户目录、显示首页及工作簿、处理系统文件对话框和关闭确认。 |
| 启动页 | `apps/desktop/home/app.jsx`、`third_party/desktop-apps/common/loginpage` | 使用上游 Solid 组件及样式，保留首页的最近文件列表和打开页的最近文件夹，通过上游桌面接口获取历史。 |
| 编辑器与桌面桥接 | `third_party/desktop-sdk` | 在 Qt 中嵌入 `QCefView`，`CCefViewEditor::OpenLocalFile` 接收用户选择的路径。SDK 把编辑、修改状态和保存事件连回宿主。 |
| 表格引擎与编辑界面 | `third_party/sdkjs/cell`、`third_party/web-apps/apps/spreadsheeteditor` | 提供网格、公式栏、公式计算、工具栏和工作表标签。 |
| 本地格式转换 | `third_party/core`，运行时的 `converter/x2t.exe` | 桌面 SDK 协调 XLSX 的导入和保存。所有单元格修改都在同一个编辑会话里提交。 |

### 依赖版本

五个 Git 子模块的提交都取自 `DesktopEditors v10.0.0` 的发布树。主仓库的 gitlink 记录精确提交。构建时通过 SDK 头文件编译本项目 Qt 宿主，从固定版本的官方 Windows x64 运行目录归集预编译 DLL、CEF、编辑器资源、转换器和字体，并从 `desktop-apps` 源码重新构建精简启动页。开发者可以将解包好的运行目录传给脚本。升级时同步更新五个指针、运行文件版本检查和前端锁文件，再跑文件往返验收。[上游发布树](https://github.com/ONLYOFFICE/DesktopEditors/tree/v10.0.0)

### 项目规范

- Qt 主窗口持有工作簿视图。SDK 回调切回 Qt 线程并核对发送者；以 SDK 的保存完成事件决定是否结束会话。
- 首页和打开页优先使用上游组件及本地化资源。项目差异保存在 `apps/desktop/`，构建时在暂存目录合成。修改子模块本身时使用可追踪的上游提交或 fork。
- 财务工具与启动页共用 Solid 界面。带预览的工具使用 SheetJS。同表头合并通过随包的 `HeaderMerge.exe` 顺序读取工作表 XML 并压缩写入结果，按当前工作簿加载共享字符串和数字格式。Qt 负责文件对话框、进度、取消和最终文件替换。
- 文件回归使用临时工作簿和独立用户目录。测试应同时验证正常退出、磁盘文件内容、最近记录和重启后的编辑器值。界面及后续面板的详细约定见 [UI 设计与交互规范](docs/ui-interaction.md)。

## 本地构建与打包

在 Windows x64 使用 PowerShell 7，准备 Git、Visual Studio 2022 x64 C++ 工具及 Windows SDK、CMake、Ninja、Qt 5.15.2 MSVC x64 开发包、Node.js 22（含 npm）和 Inno Setup 6.7。下面两个参数分别是开发机上 Qt 的套件目录和包含 `ascdocumentscore.dll` 的官方 10.0.0.169 x64 运行目录。

```powershell
git submodule update --init --depth 1
./scripts/build.ps1 -QtDir 'C:/Qt/5.15.2/msvc2019_64' -Runtime 'C:/Program Files/ONLYOFFICE/DesktopEditors'
node --test ./tests/finance-tools.mjs ./tests/header-merge.mjs ./tests/research-tools.mjs
./tests/verify.ps1 -Runtime ./dist/ExcelUtils
ISCC.exe ./packaging/windows/ExcelUtils.iss
```

`scripts/build.ps1` 调用 MSVC 和 CMake 编译客户端、用 npm 锁文件构建首页，并生成 `dist/ExcelUtils/`。`-NativeOnly` 适用于已有完整运行目录时迭代 C++。`packaging/windows/ExcelUtils.iss` 将运行目录和许可说明打成单个离线安装器。随包的 `NOTICE.txt`、`ONLYOFFICE-LICENSE.txt` 和第三方许可文件说明组件来源。[ONLYOFFICE 发布版许可证](https://github.com/ONLYOFFICE/DesktopEditors/blob/v10.0.0/LICENSE) · [Qt 开源许可说明](https://www.qt.io/development/open-source-lgpl-obligations)

## 验收方式

`tests/verify.ps1` 启动真实 Qt 客户端，在含中文和空格的临时路径中创建测试工作簿。从“打开”页选文件，在编辑器中修改 A1、保存并退出。测试独立读取磁盘 XLSX 的工作表 XML 和字符串表，再重启客户端，检查四个导航入口、最近文件夹，并从最近文件列表打开工作簿核对 A1。还会检查主进程从被测应用目录加载 Qt、CEF 和桌面桥接 DLL。可以将 `-Runtime` 指向安装后的目录复测。运行测试需要本机可用的 8080 端口和 Windows 桌面会话。

运行 `./tests/verify.ps1 -SaveOnClose` 可验证另一条路径：修改单元格后直接关窗，在未保存确认框选择“保存”，等待客户端退出，再检查磁盘和重开结果。
